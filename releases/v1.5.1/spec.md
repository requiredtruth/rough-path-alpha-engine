# Rough Path Alpha Engine — v1.5.1

## Installation and identity
Signed Android APK, package `com.roughpath.alpha`, Android 8.0/API 26 minimum, API 35 target. Android 10+ supports direct report export to Downloads. Install RoughPathAlpha.apk from the GitHub release. It installs alongside TwinTrade. No account or subscription is needed for market data or backtesting. Live execution requires a funded Polygon wallet with native USDC collateral and POL gas.

Live price frames reject stale, future, malformed and out-of-order samples. The native foreground monitor continues when user-enabled; notifications and battery permissions are handled by Android. Polygon chain 137. Trading Diamond `0x209A9A01980377916851af2cA075C2b170452018`; native USDC `0x3c499c542cEF5E3811e1192ce70d8cC03d5c3359`, six decimals. Gas, oracle skew, historical fee tiers and market impact are not reconstructed by the backtester.

## Rough Path indicator
The turquoise line and signal strip overlay the selected market. Parameters are persisted per app: rolling sample window, score threshold, efficiency gate, signature area weight, noise passthrough gain, band volatility window, band multiplier, projection slope window, horizon and score weight. Defaults: window 32, threshold 0.8, efficiency 0.1, area weight 1, gain 0.18, band window 32, band multiplier 1.5, projection window 16, base horizon 12 samples, rendered/evaluated horizon 36 samples, projection weight 0.5.

For each rolling time/log-price path, level-2 signatures are computed with Chen concatenation for piecewise linear increments. For a segment increment d, S2 += S1 tensor d + 0.5 d tensor d, then S1 += d. The antisymmetric area is (S12−S21)/2. Time is normalized within the window. Prefix sums compute this rolling area in O(1) per sample. A lead–lag lift's area magnitude equals half the summed squared log-price increments. This quadratic variation normalizes directional return and area; efficiency equals absolute net log return divided by total absolute log variation.

Raw score = log return / sqrt(quadratic variation) + areaWeight * area / sqrt(quadratic variation). The structural score scales by (0.5 + 0.5 * smooth), where the legacy `smooth` parameter now controls noise passthrough rather than EMA smoothing. The price center is a causal geometric play operator: tube = close * sqrt(QV / window) * (1 - efficiency) * (1 - smooth); center = clamp(previousCenter, close - tube, close + tube). Straight directional paths pass without EMA phase lag; reversals inside the tube can still have threshold response delay. A truncated signature alone does not remove all microstructural noise, and time-augmented paths are not globally invariant under arbitrary time reparameterization.

Signals require ready windows, the efficiency gate, score threshold, and a matching price residual against the geometric center (nonnegative for long, nonpositive for short). The adjusted score adds projectionWeight times a bounded slope estimate normalized by base channel half-width. This replaces the former lag-driven border-breakout rule. Old optimization reports are displayable but cannot be applied until rerun with engine 1.5.1. Gap fills are excluded; gaps reset warmup. Historical optimizations have no live skew observations and cannot reconstruct historical OI/CVD/funding.

### Upper/lower borders and dotted projection
Gold upper and rose lower borders enclose the turquoise causal center. Channel half-width = bandMult * center * max(1e-6, sqrt(sum of squared log returns over bandWindow)). A faint fill helps distinguish the channel from trade/liquidation lines. Channel warmup and gap resets suppress signals until all required windows are ready.

Each dotted line starts at the exact current value of its own solid counterpart. Its own least-squares slope is fitted over projectionWindow recent samples; when that slope opposes the last segment's direction, the last segment slope is used so the continuation does not immediately point the wrong way. The projected horizon is three times projectionSteps: a base value of 12 renders 36 future samples. The center and both borders have separate trajectories. Borders are bounded against the center if extrapolated lines would cross, and prices stay positive. These are visual extrapolations, not real future prices or guaranteed confidence bounds.

Projection score contribution uses the same direction-adjusted center slope over the triple horizon: projectionWeight * clamp(slope * (3 * projectionSteps) / current half-width, -5, 5). Thus the searched base horizon participates in the actual strategy. A zero projection weight remains an available baseline.

The chart computes the overlay on the selected candle timeframe, shown in the chart details and signal strip. Its lookbacks and horizon count these chart samples. Research uses the selected historical dataset's samples (one-minute candles or ticks), so parameters tested on one-minute data correspond directly to the one-minute chart. On larger chart timeframes the same algorithm is recalculated at that resolution. Projections appear only at the latest edge, with no hindsight projection while panning old data. The chart reserves future space dynamically so the extended forecast is visible. The price scale includes visible channel and projection bounds. Center, borders/fill and dotted projection visibility are independently adjustable. This is an original channel presentation; no proprietary LuxAlgo source or formula is used.

### Calendar month and six-month views
Zoom includes **1 month** and **6 months**, using UTC calendar-month subtraction with valid month-end clamping, plus Min zoom at six months. Monthly charts download actual Coinbase hourly OHLCV in 200-hour pages, with persistent cache reuse, incremental extension, progress and transient-error retries. Additional lookback history warms up the indicator before the visible range. The month preset defaults to four-hour display candles and six months to daily display candles; users can choose hourly or larger candles. No minute-sized historical array is manufactured from hourly data. Missing hours are disclosed and not filled. The latest observed Gains minute candles supply a marked partial current hourly candle, while execution and live PnL continue using Gains oracle marks and index prices.

Research also includes **1 month** and **6 months** date presets for its existing resumable one-minute downloads and parameter search. Its data cache remains separate in namespace from the lightweight chart's hourly pages.

This is an original practical indicator inspired by rough-path signatures. It is not a proof that noise filtering yields profitable alpha. The signal and turquoise line are research outputs, not an exact solution of a stochastic differential equation.

## Historical data
Research screen: Rough α button near Stats. Select UTC from/until dates, exclusive until. Last year defaults to 365 completed days, last week to seven. Coinbase Exchange BTC-USD one-minute OHLCV uses 200-bucket pages below the 300-bucket API limit. Typical year: approximately 525,600 samples and 2,628 pages. Leap-year full-calendar data can have 527,040 samples. One book supports 600,000 minute buckets; split larger studies into separate date ranges. The app downloads data itself; no year-sized dataset is bundled.

Each page is normalized, sorted, deduplicated and committed to IndexedDB before checkpoint progress advances. Pausing or interruption leaves committed pages reusable. HTTP transient failures retry with exponential backoff; permanent HTTP 400/401/403/404 fails visibly. Empty or incomplete candle windows are counted as unavailable rather than filled. Retry missing candles deletes sparse cached pages and refetches them. Interrupted jobs resume by pressing Download / resume with the same dates. UI downloads and workers run while the app remains active; Android may suspend or kill research work in the background. Reopen and resume cached downloads. Completed results and the last valid data range, grid and cost settings persist.

Actual Coinbase trade ticks use `/products/BTC-USD/trades?limit=1000&after=...` with the oldest trade ID as the pagination cursor. Pages and cursor are checkpointed separately in the same cache. Tick IDs deduplicate samples; equal timestamps retain deterministic trade ordering. Downloads stop after crossing the requested start. API errors, archive exhaustion or non-advancing cursors remain visible; partial data is not labeled complete. Since this API walks backward from the latest trades, older dates can require substantial download time and storage. Tick optimization is capped at 1.1 million samples per book. A year of candles and a year of ticks have very different resource requirements; choose shorter tick books. Candle data is always labeled candles, not ticks.

JSON OHLCV import: array of `{t,o,h,l,c,v}`, timestamp in milliseconds, sorted unique timestamps, valid positive OHLC, rows within the selected date interval, max 32 MB per imported file. Android system file picker is used. No synthetic historical prices are inserted.

## On-device optimizer and simulator
Dedicated Web Worker keeps the terminal responsive. Packed transferable Float64 sample buffers avoid cloning all candle objects into the worker. Rolling features are reused across candidates sharing a window. Grids accept up to 20 comma-separated values per dimension and at most 512 candidates. Default grid has 256 candidates. Pause/cancel terminates optimization immediately; completed reports are retained.

Chronological splits: first 60% training, next 20% validation, final 20% holdout. Each split begins with fresh simulation cash and no position. Prior samples may warm up features, but no positions carry across splits. Candidates are ranked by min(training ROI − 1.5 * drawdown, validation ROI − 1.5 * drawdown), with at least five trades in both selection splits. Final holdout is evaluated only after selecting the best candidate. Repeated human tuning after inspecting holdout invalidates its status as untouched.

Signals from sample i act at sample i+1 open. Position size is an editable percentage of current cash, with one position at a time; neutral or reversed signal closes the position. Leverage ranges from 1x to 500x. Editable opening/closing fee and adverse slippage apply to notional, plus time-based borrowing and signed funding. Intracandle high/low triggers the estimated liquidation threshold, with adverse gap-open handling. Position loss is capped at collateral. Entry costs that already breach liquidation are skipped. Missing minute gaps above 90 seconds or tick gaps above five minutes close positions at the last available price and reset indicator features. This explicitly assumes liquidation at last quote for gap separation, not knowledge of prices within the gap. OHLC cannot reconstruct the complete ordering of intraminute prices.

Report: ROI, max drawdown, trades, win rate, fees, holding cost, profit factor, candidate parameters, selection score, chronological date splits, gaps, skipped costly entries and holdout equity curve. Export JSON to Downloads. By default, the best eligible current-engine parameters are applied to the live chart after a search. This can be disabled; Apply selected indicator copies them manually. Prior-engine reports remain visible but must be rerun before applying to the new channel strategy; it does not place orders. Automatic optimization after download is enabled by default and can be disabled. The optimizer searches all ten indicator dimensions plus leverage (1–500x) and collateral allocation (>0–100% of current equity). Lists and inclusive `min:max:step` ranges define finite domains; each axis supports up to 10,001 values. The Cartesian product is counted exactly with BigInt and decoded lazily, never materialized in memory. The old 512-candidate optimizer limit is removed. A run evaluates 1–1,000,000 unique candidates, clamped to the available space.

Methods: **grid** visits every combination in deterministic order when the budget covers the space; **random** uses seeded uniform proposals without duplicate evaluations; **simulated annealing** changes neighboring parameter indices, accepts worse scores with `exp(delta/(temperature * scoreScale))`, cools geometrically from 1 to 0.01 over 250 proposals, and restarts from the best candidate every 250 proposals; **hybrid** allocates approximately 20% of the budget to evenly spaced grid exploration, 40% to random sampling, and the remainder to annealing. Duplicate proposals fall back to random exploration and eventually unvisited grid entries, guaranteeing unique evaluations even near exhaustion. The seed makes proposals reproducible for unchanged data and settings. No method guarantees the global optimum on an incompletely covered space.

The Huge search preset defines broad indicator ranges, every integer leverage from 1 through 500, and every integer collateral percentage from 1 through 100, with a 100,000-candidate hybrid budget. This is sampled coverage of the displayed much larger domain. Budget for entire space selects exhaustive grid mode only for spaces with at most 1,000,000 combinations; narrow ranges to exhaust larger spaces. Continuous real-valued possibilities cannot all be enumerated: selected step sizes define coverage. Fees, slippage, funding, borrowing, liquidation threshold and initial balance remain explicit fixed assumptions rather than optimizable market costs.

Candidate-specific leverage and collateral are used on training, validation and the final selected holdout. Indicator signals/features are reused for adjacent identical settings, with a bounded one-entry cache. Only ten leaders and visited candidate identifiers are retained. Reports record selected risk, method, seed, finite domain, unique count, full/sample coverage, elapsed time, annealing acceptance/restarts and numerical rejection count. Candidates with nonfinite equity or compounded equity exceeding 1e100 are rejected without terminating the other searches; a numerically invalid holdout is labeled unevaluable. Selected risk settings do not alter live order controls. Indicator parameters alone can be auto-applied.

Progress displays method, coverage, best risk, train/validation ROI, elapsed time and estimated remaining time. Huge annual-data studies may require hours or days; cost grows with dataset size times evaluated candidates. Keep the app active. The worker isolates computation from chart rendering but does not survive Android process termination. Cancel discards an unfinished search; downloaded history remains cached. The app does not label sampled exploration as exhaustive.

## Full-spectrum live OI / spot / funding skew (1.5.1)
The gold/rose borders and matching dotted projections use combined Arbitrum (42161), Polygon (137), and Base (8453) exposure. Each chain has an independent open-trades snapshot and collateral/pair registry. Market identities are resolved by symbol using that chain's own pair indices. Regular and DEGEN variants are combined by underlying asset. For every collateral with verified metadata, position notional = raw collateral amount / collateral precision * raw leverage / 1000 * current collateral USD price. All collateral types are eligible; absent USD prices are excluded and counted as partial coverage. No token amount is assumed to equal USD. Identical user/index values on different chains remain distinct; duplicates within one chain are removed.

Long OI accumulation uses snapshots at least one minute apart. Previous collateral-unit exposure is revalued at current collateral USD prices before computing growth, so a rising ETH collateral price alone cannot masquerade as new long positioning. Chain/registry coverage changes reset comparability. Per-chain long/short USD exposure, unpriced-position counts, and availability are shown in the Rough α coverage table; the main chart identifies participating chains. Funding is fetched for every contributing chain/market/collateral group and weighted by its long USD notional. A missing contributing funding rate disables skew rather than silently becoming zero or borrowing another chain's rate. Polygon execution fee settings remain separate from these indicator-only multi-chain rates.

Spot CVD uses continuous Coinbase Exchange matches + heartbeats and Kraken v2 trade streams for the selected USD crypto asset, with automatic reconnection. Coinbase side is the maker side (sell means taker buy); Kraken side is the taker side (buy means taker buy). Flow is signed USD trade notional over a two-minute window. Per-venue/book trade IDs suppress duplicates and detect gaps; reconnects, heartbeat gaps or missing IDs reset a two-minute warmup. Second buckets bound accumulation memory, rather than sampling the latest 100 trades or retaining every print. Only warmed, fresh venues contribute. Venue coverage is displayed (Coinbase/Kraken, up to 2/2); this is coverage of those venues, not a claim to cover every exchange worldwide. Unsupported spot pairs, closed/throttled sockets, missing rates and offline chains are explicitly unavailable/partial. Foreground streams resume and warm up after suspension; historical or background spot flow is never fabricated.

Let clip clamp to [0,1]. Weakness = clip(-signedSpotNotional / totalSpotNotional); crowding = clip((longOI-shortOI)/(longOI+shortOI)); growth = clip(longOIGrowthFraction/0.02); fundingStrength = clip(longFundingDecimalPerHour/0.00001). Pressure = weakness * crowding * growth * (0.5 + 0.5*fundingStrength). Upper = center + baseWidth*(1-0.8*pressure); lower = max(1e-9, center-baseWidth*(1+0.5*pressure)). This compresses upside and expands downside when longs accumulate against weak spot flow. Pressure is a heuristic, not a liquidation probability. The geometric center is unchanged by skew.

Observation components expire after 120 seconds; spot stream activity must be recent within 15 seconds. Missing, nonfinite, future or invalid inputs result in neutral symmetric bands. Observations are bounded session memory, joined as-of candle end (or current time for the open candle), and never backfilled onto earlier candles. The historical optimizer has no invented OI, funding or spot-flow history. Full configured coverage means 3 fresh, fully priced chains and 2 warmed spot venues with funding for all contributing long exposure. Partial operation remains labeled rather than described as complete.

## Network resilience (1.4.0)
Read-only Gains HTTPS requests and price/public WebSockets have service-specific gains.trade → gains.dev fallback, including DNS, TLS, socket, timeout, HTTP and invalid-JSON failures. Native Android background prices/history and foreground charts, holdings, registry, multi-chain public trades and candle history are covered. Service paths, chain IDs and queries are preserved; HTTPS/WSS and certificate verification stay enabled. A blocked secondary remains unavailable and retries; the app never treats a hostname alone as proof of health. Read failures never resubmit signed orders.

Primary health is retried after 60 seconds. Foreground WebSockets perform make-before-break recovery: a primary probe must deliver a valid application frame (fresh prices for pricing) before replacing the working secondary. Native background monitoring uses the same fresh accepted-price requirement. Connect/first-frame and stale-stream deadlines prevent stuck sockets. HTTP and WebSocket circuits are independent. Exact service hosts are allowlisted by suffix, excluding lookalike domains. Local probes on 2026-10-16 returned HTTP errors from both domains in the build environment; public Internet outage status and secondary availability could not be independently verified.

## Python pipeline module
`pipeline/rough_alpha.py` provides `Signature2` (Chen append and prefix inverse), `RoughPathIndicator` (O(1) per tick, O(window) memory), `Microstructure`, `deform` and `ReadRouter` (stdlib read-only JSON fallback/recovery). It shares the chart's geometric feature, deadband and skew equations for equal feature/band windows; its `structural_score` omits the chart-specific OLS forecast contribution. `pipeline/spectrum.py` adds chain-local all-collateral USD normalization and OI-weighted funding aggregation with repricing-neutral growth. Pass chronological millisecond tick timestamps and positive prices; pass only observations already known at that tick. No automatic execution or key handling is included. See `pipeline/README.md` for integration.
